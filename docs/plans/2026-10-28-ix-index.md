# IX: The index

> T6's ninth slice. **Full tier**: a new inline node in stored content, a layout member and the
> default layout's 0.14 (0169), a published-document schema and template, Word fields carrying
> content. Ken chose it on 2026-10-28 and answered its four questions the same day, each as
> recommended: those are marked **(Ken)**, the rest **(default)**.
> **The requirements are thin, not wrong.** STR-043 and PUB-041 say an index is generated where a
> layout declares one from marked entries, and nothing of what an entry is; Ken's answers and this
> plan's defaults say it, in the design, not in new rows. STR-Q03 ("is an index in scope at all") is
> answered by this slice and closed with a change history; both rows stay `should`.

**Goal:** an author marks index entries in a component's text; a document whose layout places an
index publishes one, sorted in its language, with page numbers in the PDF, fields Word fills in Word,
and section links in HTML (STR-043, PUB-041).

## Decisions

| ID   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| IX-A | **Two levels** (Ken): a term and an optional sub-entry.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| IX-B | **See and see also** (Ken): a "see" marker locates nothing; a "see also" stands beside its term's locators. Either naming a term no marker in the published document carries fails `index_reference_unresolved` (compose, `detail` `see` or `seeAlso`, never the words), naming the marker's node and block. A term both located and redirected by "see" fails `index_see_located`, naming the "see". Checked only where the layout places an index.                                                                                                                                                                                                    |
| IX-C | **Point entries only** (Ken): ranges are a named gap in the design.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| IX-D | **HTML's locator is the section** (Ken): the innermost node holding the marker, by its number, or its title where unnumbered, a link to the marker; a section repeated under one entry is one locator.                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| IX-E | **The marker** (default): `{ type: 'indexMarker', term, sub?, see?, seeAlso? }` in `inline.ts` beside `citationNodeSchema`: an atom with no `id` (anchors are `assemble`'s, IX-I), no marks, **no sort key** (a named gap: collation alone orders). Each string NFC, 1 to 200 characters, one line, visible, as layout words are (`layout.ts`'s `words`); `see` a term, `seeAlso` 1 to 10 terms, the two exclusive. It stands wherever a citation does (`schema.ts`'s content expressions), never in a section title. Content schema 1, in place, as `citation` was.                                                                                    |
| IX-F | **Write paths** (default), each tested to keep every attribute: the editor schema node and `mapping.ts` both ways, `marksWithNoType` among them (a node the schema lacks is dropped on save); `checkInlineContent` (`model/document.ts`); the product clipboard. Having no `id`, `reidentify` and import's matching (`import/changes.ts`) pass it untouched, tested. No `parseDOM`, for a footnote's reason, so a paste from HTML, Markdown or text never makes one; the assistant is not offered it. Word's `XE` fields stay tallied by `docx.ts` as other fields: reading them is a named gap. No Postgres check reads inline types, so no migration. |
| IX-G | **Translated** (default): `xliffUnits` sends a marker as a placeholder, as it does every atom, and its term, sub-entry, "see" and each "see also" as `words` units of their own after the text, as an image's own alternative is (`xliff.ts`), so a variant's index is in its language; machine drafts follow through `xliffUnits`.                                                                                                                                                                                                                                                                                                                     |
| IX-H | **The layout** (default): `matter.index?: { title, see, seeAlso }`, **added at 9 in place**, as `glossary` was at 7: a layout without one places none, so no schema 10. A translation gives `titles.index?: { title, see, seeAlso }` where the layout places one (`translationGaps`), and `layoutIn` carries it. The default layout's 0.14 places it: Index, see, see also; fr Index, voir, voir aussi; de Register, siehe, siehe auch; 0169 inserts it where 0.13 is still latest, as 0168 did.                                                                                                                                                        |
| IX-I | **Assembled** (default): from the resolved document, after conditions and profiles (PUB-042), in reading order; anchors `x-<n>` by that order. Entries merge on the NFC term, sub-entries on the term and sub-entry; sorted by `collatorFor` of the document language (`terms.ts`), a term's own locators before its sub-entries; **no letter groups** (a named gap: initials need CLDR's index characters). `back.index` after the abbreviations, set only where it has an entry. A marker under a layout with no index prints nothing and fails nothing.                                                                                              |
| IX-J | **The PDF** (default): `publishing/27`, template 27. A marker sets `#metadata(none)` labelled with its anchor, as a bibliography entry's label is set; the index after the abbreviations, its title a heading kept out of the contents and bookmarked, as `back-list`'s; entries a list (`L`/`LI`), sub-entries a nested list. Each locator is the anchor's page in its matter's numbering (`reference-run`'s rule), a link, one per page. "See" and "see also" are the layout's words, emphasised. A caption set again in the lists labels its marker once.                                                                                            |
| IX-K | **Word** (default): an `XE` at each marker, `term:sub`, its `"`, `\` and `:` escaped so content never reaches a switch; "see" as `\t`; then an `INDEX` field prefilled with the entries in `Index 1` and `Index 2` and **no page numbers**, which only Word can know, as the `TOC` is (`write.ts`); `updateFields` already set. Word re-sorts on update by its own collation: the Word check records where it differs.                                                                                                                                                                                                                                  |
| IX-L | **HTML** (default): a marker is an empty `<span id>`; the index a `<section aria-labelledby>` after the abbreviations, nested `<ul>`, locators as IX-D, "see" and "see also" in `<em>`; through `escapeText` and `escapeAttribute`. The leak scan reads all three outputs as it does now; a marker in excluded content is tested to reach none, its `XE` included.                                                                                                                                                                                                                                                                                      |
| IX-M | **The editor** (default): an Index entry action (Mod-Alt-i, free today) opening a dialog of term, sub-entry, "see" and "see also"; the marker drawn as a chip whose accessible name says it and its term, opened to edit, printing nothing: the read text and word count skip it, plain-text copy drops it.                                                                                                                                                                                                                                                                                                                                             |
| IX-N | **Claims** (default): PUB-041 and STR-043 in full, in publishing.md's `## The index`; structure.md's STR-043 row points there. Tagging is `L`/`LI` (PDF/UA-1 has `Index`, the pinned Typst cannot write it: named, as CI named `BibEntry`). No report kind: nothing is dropped.                                                                                                                                                                                                                                                                                                                                                                         |
| IX-O | **Conformance** (default): a corpus case with markers in front matter, the body, a footnote, a table and a caption, sub-entries, "see" and "see also", in en and fr; PDF through veraPDF, HTML through axe and the walks, Word through the Word check; each pinned.                                                                                                                                                                                                                                                                                                                                                                                     |

## Risks

- **Labels set twice**: a caption is set again in the lists, and Typst refuses a link to a label set twice;
  measured in IXb before the template is written.
- **Merging on the exact term**: "Alloy" and "alloys" are two entries; the dialog offering the
  component's own terms is the only help at IXd.
- **Word's re-sort** may order an updated index unlike the PDF's; recorded, not fought.
