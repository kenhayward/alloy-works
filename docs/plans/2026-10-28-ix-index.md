# IX: The index

> T6's ninth slice. **Full tier**: a new inline node in stored content, a layout member and the
> default layout's 0.14 (0169), a published-document schema and template, Word fields carrying
> content. Ken chose it on 2026-10-28 and answered its four questions the same day, each as
> recommended: those are marked **(Ken)**, the rest **(default)**.
> The pre-flight review's findings are folded in.
> **The requirements are thin, not wrong.** STR-043 and PUB-041 say an index is generated where a
> layout declares one from marked entries, and nothing of what an entry is; Ken's answers and this
> plan's defaults say it, in the design, not in new rows. STR-Q03 ("is an index in scope at all") is
> answered by this slice and closed with a change history; both rows stay `should`.

**Goal:** an author marks index entries in a component's text; a document whose layout places an
index publishes one, sorted in its language, with page numbers in the PDF, fields Word fills in Word,
and section links in HTML (STR-043, PUB-041).

## Risks

- **Labels set twice**: Typst refuses a link to a label set twice, and HTML a repeated id; IX-I drops
  copies, and IXb measures captions and repeated header rows before the template is written.
- **Merging on the exact term**: "Alloy" and "alloys" are two entries; the dialog offering the
  component's own terms is the only help at IXd.
- **Word's re-sort** may order an updated index unlike the PDF's; recorded, not fought.

## Built

IX in four PRs: IXa #804, IXb #805, IXc #806 and the close #807. Departures: **Index entry** is on
Mod-Shift-1, beside Cite's 2, not Mod-Alt-i, which is Cmd, Option and I, every Mac browser's developer
tools. The dialog's "see also" is one term a line, and it refuses as the content model does, naming the
member, after holding what is typed in NFC, trimmed. The gap IXa left, a proposal replacing a paragraph
dropping its markers, is closed in `applyEdits` rather than shown in review: a replacement keeps the
replaced block's markers at the end of its first paragraph. The walks cover the chip and the dialog:
axe in the editor walk, the chip in the navigation walk's components and the pseudo walk's dialog in
both pseudo-locales.
