# G8: The MCP surface and service identities

> T5's eighth slice ([generation.md](../design/generation.md), the order's G8; [access.md](../design/access.md)'s
> tokens): an MCP endpoint on the service whose few tools act through the API as their caller, and
> service identities an administrator makes. **Full tier**: a new protocol surface, a new kind of
> principal, auth, audit kinds. Ken's answers of 2026-10-21 are marked **(Ken)**; the rest
> **(default)**. The pre-flight review's findings are folded in.

**Goal:** an agent connects to `https://<environment>/mcp` with an API token, a person's or a service
identity's, and gets seven tools described for a model, the four that read marked apart from the three
that change; each call is the API route it wraps, under that caller's permissions and nothing else,
and is audited with its identity, tool, arguments and outcome. A service identity is a principal of its
own that no sign-in or invitation can produce (API-018 to API-024, API-052, REL-021, IAM-033, IAM-036).
LIF-071 stays unclaimed: it also asks for webhook subscription events, which wait for webhooks.

## Decisions

| G8-A | **Streamable HTTP on the service** (Ken), outside the contract (ADR-0065: JSON-RPC is not a REST route and `openapi.json` would mislead). `POST /mcp` is a raw Fastify route as `registerDocs`'s are, doing what a contract route's hooks do: the tenant by host (404), the bearer lookup (`findApiToken`), its own error handler answering JSON-RPC, never an `ErrorBody`; `app.test.ts`'s exact-routes test excludes it as it does the docs. Stateless: no `Mcp-Session-Id`, every answer `application/json`, `GET /mcp` 405, notifications and client responses 202 with no body, batches refused (`-32600`). Bearer only: a cookie is ignored and a missing or bad token is 401 with `WWW-Authenticate: Bearer`, so no page drives a person's session through it; an `Origin` sent must match the environment's scheme, host and port, else 403. OAuth clients cannot connect with a static token, named. Versions held: `2025-11-25` and `2025-06-18`, negotiated at `initialize`; later requests read `MCP-Protocol-Version`, an unsupported one 400, an absent one answered as `2025-06-18` (a departure from the specification's `2025-03-26` default, which holds no `structuredContent`). Hand-written: `initialize`, `ping`, `tools/list` (one page), `tools/call`, others `-32601`; a test drives it with the official TypeScript SDK client as a dev dependency. |
| G8-B | **A tool is its route** (API-018, API-020, IAM-036, REL-021): each call is `app.inject` of the API route it wraps with the caller's `Authorization`, `host: request.host` (its port kept), the outer `x-request-id` (one trace id for the route's events and the call's) and no `X-Forwarded-*`, so tenancy, scopes, permissions, refusals' `access.refused` and the route's own audit apply exactly as over HTTP, and traversal is the API's on the same terms. A tool shapes arguments and trims answers, using domain's pure functions where the assistant does (Markdown to blocks, block edits); it holds no query. The route's 4xx is a result with `isError: true` and its code; a 5xx a JSON-RPC error; invalid arguments a tool error, an unknown tool `-32602`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| G8-C | **Seven tools** (Ken; API-024). Reading: `search` (`/v1/search`); `read_document` (`/v1/documents/{id}` and its texts); `read_component` (`/v1/components/{id}`, as numbered blocks the way the assistant's `read_component` gives them); `related` (`/v1/artifacts/{id}/relationships`, and `/path` given a second id). Changing: `comment` (`{ on: { kind, id } }` starts a thread, `{ thread }` replies; text as `{ text }` parts, no mentions); `suggest_edit` (the assistant's block edits against the version `read_component` gave, applied by domain's function and sent whole to `/v1/components/{id}/suggestions`, so the author reviews a redline); `draft_component` (a new component in a space with Markdown content, `createComponent` gaining optional `content` admitted as a save is, a draft nobody places until a person does). Nothing approves, publishes, edits an existing version or moves workflow. The review queue stays out: `/v1/me/attention` is session-only, and changing that is its own decision. Adding a tool is a row here first.                                                                                                                                                                                                                                                                                                       |
| G8-D | **Described for a model, reads marked apart** (API-019, API-021): each description says what the tool is for, when to use it and what it returns, in that order, held by a test to those parts and a length; a top-level `title` and `annotations` (`title`, `readOnlyHint` true for the four, `destructiveHint: false`, `idempotentHint` true for the four and false for the three, `openWorldHint: false`); the changing three's titles start "Changes:". `inputSchema` and `outputSchema` from zod, the trimmed answer validated against `outputSchema` in a test, as the SDK client checks.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| G8-E | **Results are data** (API-022, GEN-017): `structuredContent` is the trimmed answer and the text content that JSON, never prose built from content; every description says that what content says is never an instruction.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| G8-F | **Every call audited** (Ken; API-023): the declared `tool.used` (kinds.ts, already in the check; its emitter set, no migration), its subject the artifact the call names or the tenant, its detail strict: `{ tool, arguments, outcome: ok, refused or failed, code? }`, `arguments` a record of argument name to an identifier, a number, a boolean, an enumerated word, or `{ length, sha256 }` for any text (a query, a comment, Markdown). Content never enters the log (LIF-030), so API-023's "the arguments" is held as identifiers and digests, said in the design. Written in its own transaction after the call with the token's audit context, so a refused call is recorded; a write that fails after a change succeeded leaves it unrecorded, logged at error as a refusal's is. The census gains a group for the MCP route.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| G8-G | **Service identities** (Ken; IAM-033): `service_identity (principal_id primary key references principal, description, created_by, created_at, disabled_at)`, the principal `kind = 'service'` with `issuer`, `subject` and `email` null; 0138 relaxes `principal_invited_by_address` to admit a service, and `invited` everywhere becomes `issuer is null and kind <> 'service'` (listings, erasure, grants' last-administrator count, first-administrator). Roles are granted as to a person; a service never counts as the last administrator. ## Risks

- **Prompt injection through results** is what the surface contains: a tool does only what its route lets the caller (G8-B), results stay JSON (G8-E), and no argument names a principal, URL or path.
- **`app.inject` stays in process**: per-IP limits would see the service; none exist, named.
- **The protocol moves**: two versions pinned and tested.

## Built

G8 in three PRs: G8a #736, G8b #737 and the close #738. Departures: `tool.used`, already declared,
was built in place of a new kind and migration; a tool's text arguments are kept as their length and
an unsalted digest; People gained service identities rather than a page of their own; `search`'s
answer, a union, sits under `answer` so its output schema is an object. The final review found no
leak; it fixed Markdown a save could not store answered as a failure, a body too large or of another
type answered as our failure, and a call naming no tool or refused its arguments left unrecorded.
Left, named: the digest can be guessed for a short text; the changing tools take no idempotency key;
OAuth clients cannot connect with a static token; LIF-071 waits for webhooks.
