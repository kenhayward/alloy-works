# WF1: Workflow definitions and states

> T9's first phase ([ADR-0061](../decisions/0061-t9s-order.md)), designed in a new
> [workflow.md](../design/workflow.md). **Full tier**: stored shapes (migration 0095), new routes and a
> stream event; a pre-flight review and a final review. Decisions marked **(default)** are
> recommendations Ken may overturn.

**Goal:** every component and document is in exactly one workflow state, shown wherever it appears;
a tenant administrator declares the states and transitions for each kind, versioned, starting from
draft, in review, approved; whoever a transition permits moves an artifact along it, with a reason
where the transition asks for one, audited; search narrows by state (LIF-001, LIF-002, LIF-005,
LIF-007, LIF-061, SCH-060, LIF-054). LIF-036 and LIF-075 each ask for an approval too, phase 2's, so
workflow.md names their gap rather than claiming them.

| WF-A | **Per kind** (default): one workflow for components, one for documents, as LIF-019's keeps are per kind (Ken, 2026-10-14). Per component type or template is a later override, not built. Query definitions join in phase 2 (DAT-121).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| WF-B | **A definition** is an insert-only `workflow_definition (id, kind, version_no, body jsonb, by, at)`, the latest per kind in force (keeps.ts's shape), not a fourth definition artifact (ADR-0024), which would bring routes, search and pins nothing here needs (default). Body: states (a stable key, a name, one initial), transitions (a key, a name, from, to, the permission it needs, `edit` or `approve`, whether a reason is required). Validated in domain: keys unique, every state reachable from the initial one, no transition to itself.                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| WF-C | **Seeded**: every tenant's version 1 for each kind is draft, in review, approved; Submit (draft to in review, `edit`), Return (in review to draft, `edit`, reason required), Approve (in review to approved, `approve`), Reopen (approved to draft, `edit`, reason required). Return and Approve need `approve`, so that whoever reviews (the Approver role: read, comment, approve) can do both, and an editor alone cannot approve. One person holding both roles can approve their own work until phase 2 (LIF-010).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| WF-D | **State** is an insert-only `workflow_transition (id, artifact_id, kind, version_id, transition key or null, from_state, to_state, definition_id, reason, by, at, written_by)`, guarded as `artifact_archival` (AH-C); `(definition_id, kind)` references the definition, so a component never moves under the document workflow; `version_id` is the version current at the move, for phase 2's designation and "approved, edited since". The latest row is the state and the definition version it moves under (LIF-007). `createArtifact` (versions.ts), the one place both kinds are made, writes its first row (the initial state, no transition) before indexing; 0095 backfills one per existing artifact under version 1, and `search_entry.workflow_state` in SQL. Every write is guarded by `workflowStored()`, as `archivalStored`, for older schemas; the load suite's raw inserts write rows too.                                                                                                 |
| WF-E | **The newest definition decides** (default): each move, and the transitions offered, are taken from the newest version wherever it has the artifact's state, so a tightened permission applies at once; only an artifact in a state the newest dropped moves under its recorded version. The row records the version that decided it (LIF-007). Nothing moves an artifact silently.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| WF-F | **Moving**: `POST /v1/{components\|documents}/{id}/transitions {transition, reason?}`, decided on the transition's permission on the artifact; under `lockArtifact`, re-checking after the lock: refused, by name, if the artifact moved meanwhile (the expected from-state in the request), is archived, or lacks a required reason; a deleted artifact answers as missing. No deletion lock: a move creates nothing a deletion asks about. A definition save takes an advisory lock per kind (keeps.ts). **A save of an approved artifact starts a draft** (Ken, 2026-10-14; LIF-040): the save moves it to the initial state in the same transaction, a row with no transition key and `workflow.transitioned` naming the version that was approved; the approved version is unchanged, and phase 2 designates it. The editor says so before the first save. A save in any other state leaves it. Which states count as approved is declared per state in the body (`approved: true`; the seed's approved). |

A filter and a facet on the state's key. ## Task 1: Definitions, states and transitions - WF1a

- workflow.md, its claims; domain `workflow/` (the body schema, validation, the seed, `nextDefinition`);
  migration 0095 (both tables, the seed, the backfill, `search_entry.workflow_state`, the audit kinds);
  `packages/db/src/workflow.ts`; the routes and views; the stream event; indexing and the filter.
- Tests: the seed per tenant; a save of an approved artifact moving it to draft, audited, by every save path (the component editor, a document save, a restore, a merged suggestion, a bound value revised); a body refused (unreachable state, duplicate key); a transition by
  permission, refused without it, with a stale from-state, archived, without a required reason;
  every transition audited; a tightened permission applying at once, a dropped state kept; a component never under the document workflow; a racing archive serialised; concurrent definition saves; a new
  artifact in the initial state; the backfill on an old schema; search narrowing and faceting by state, every version's search after a move, a section by its document's state; the load suite's state filter.

## Task 2: The interface and the close - WF1b

- State chips, the Lozenge's review states, the transition menu with its reason dialog, the Part
  panel, the search filter, Administration > Workflows.
- Tests: each surface shows the state; a transition from the header; a reason asked for; only the
  permitted transitions offered; an administrator's edit saved as a version; axe in Light and Dark;
  the browser walks.
- The final review hunts a state changed without a row, a transition past its permission, and a
  surface missing the state. `features.md`, `README.md`, `architecture.md`, the CHANGELOG, the
  version (0.166.0) and the baseline.
