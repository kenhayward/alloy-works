# R16: Divergent lines

> T4's sixteenth slice, extending [storage-and-versioning.md](../design/storage-and-versioning.md) and
> [workflow.md](../design/workflow.md). **Full tier**: the version chain gains a second head (0112), a
> contract change, and what an `approved` reference serves. Built inline, one final review at the
> slice's end. Decisions marked **(default)** are recommendations Ken may overturn; the rest are his
> answers of 2026-10-17. Divergence is a regulated fact, never a development workflow (LIF-N05,
> LIF-N06): nothing copies an artifact, rebases, replays or rewrites history.

**Goal:** a component can carry a divergent line of revisions - a market's wording beside the
central one - served wherever its scope applies, said wherever the component appears, and brought
back, after a comparison, block by block, with what was left behind recorded.

## Decisions

| ID    | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ----- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R16-A | **Components only** (Ken). A document follows its components' lines through their references.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| R16-B | **A line is a second head in one artifact** (default; LIF-N05): `artifact_line` names it, the designated revision it diverged from, who and when. A version carries its line, none for the main line, and a line's versions are **numbered below the main line's** ([ADR-0063](../decisions/0063-a-line-is-numbered-below-the-main-line.md)): `revision_no` the line's ordinal negated, so every read ordering by the numbers - about fifty, publishing, gates, suggestions, restore among them - takes the main line unchanged, on every schema (the pre-flight review); a read listing every version holds itself to `revision_no >= 0`. A line's number is computed for people (`US 2.3`). A line's first version's parent is the version it diverged from. |
| R16-C | **Its own workflow, one numbering of revisions** (default): a line's state and gate rounds are its own - `workflow_transition` gains the line, its `follows` trigger and insert grant per artifact and line - so saving a line never puts the main line back to draft. A designation takes the artifact's next revision number, `max + 1` across lines, so R15's "newest" holds; the revision a line's or the main line's versions count from is read per line, so the main line never numbers itself from a line's approval (the pre-flight review). `artifact_scope` gains the line, so a line's scope is its own.                                                                                                                                           |
| R16-D | **Served by scope across lines** (Ken): a line's revisions are designated and scoped as any are, and R15's rule picks among every line's; a reference never names a line. A line's revision with no scope is effective everywhere a newer scoped one is not, as any unscoped revision is, so a line's approval asks for a scope where the main line has a revision (default).                                                                                                                                                                                                                                                                                                                                                                                  |
| R16-E | **Said wherever it appears** (LIF-046): the component's view, header and versions name its open lines, what each diverged from and when, and which line the shown version is on; each occurrence in a document says the line of the revision it serves.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| R16-F | **Brought back block by block** (Ken; LIF-045, LIF-Q05): the comparison between the line's latest version and the main line's lists each block that differs; the author takes the line's or keeps the main's, block by block; the result is a new main-line version, and `line_return` records each block carried and each left behind, audited `line.returned`. No text merges inside a block.                                                                                                                                                                                                                                                                                                                                                                |
| R16-G | **It closes** (Ken): a line brought back takes no more versions; its revisions stay, effective where their scopes still apply. So that bringing it back changes what its markets are served, the main line's scope takes the line's values as it is brought back (default; the pre-flight review), and the main line's next approval supersedes the line's there.                                                                                                                                                                                                                                                                                                                                                                                              |
| R16-H | **Left as one** (default): the component's lock, search's entries and the reference index stay the main line's - editing a line holds the component's lock; a line's version is not indexed for search or where-used. Named in the Built note, not built.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
