## W7.1: The listing shape

1. **The snapshot** (`0032_listing_snapshot.sql`): `written_by xid8` on `artifact_version` and
   `publication`, added with no default so nothing is rewritten, then defaulted to
   `pg_current_xact_id()` for what is written after; a row with none is visible to every snapshot.
2. **The cursor** (`service: src/listing.ts`): `encodeCursor` and `decodeCursor` - the listing, sort,
   order, snapshot, key and id; refused where it is another listing's or unreadable.
3. **Keyset paging** (`db: src/paging.ts`): the predicate and the order for a sort key and the id, and
   the snapshot's visibility; each listing's db function takes a sort and pages by it.
4. **The routes**: `sort` and `order` on all four, `cursor` and `limit` on the three that lacked them.
   **Tests:** `SCH-022 pages without repeating or skipping while the set changes` (rows added and
   changed between pages, in both orders); uncited: each sort's order, walked a page of one at a time,
   and a cursor from another listing, sort or order refused.
5. Docs.

## W7.4: Idempotency

1. **The record** (`0033_idempotency.sql`, `db: src/idempotency.ts`): `idempotency_record` - principal,
   key, route, path, request digest, status, body, made - read and written under the key's lock.
2. **The wrapper**: the permission-checked path honours the key in its transaction; the sample route
   through the same helper. **Tests:** `API-008 answers a retried request from its record, never doing
the work twice` (a document created once for two requests with one key, the second answered with the
   first's body); uncited: a key reused for another request refused, a refusal not recorded, a day's
   expiry, concurrent requests with one key; an upload's same bytes sent again answered with the
   upload.
3. Docs; the remainder plan's W7 row reads Built.

## What the build changed

**W7.1.** Eight listings were found unpaged, not three: beside documents, publications and templates,
the per-document publications, spaces, component types, definitions and people. API-007 is about every
listing, so W7 became five pull requests: W7.1 the snapshot, the cursor and keyset paging for the
content listings, the per-document publications among them; **W7.2** the same for spaces, component
types, definitions and people, with API-007's test; **W7.3** filters, facets and the views (SCH-064);
**W7.4** idempotency keys, migration 0033 (API-008). A title sorts by the database's collation;
`changed` and `published` compare as `timestamptz`, carried in the cursor as Postgres writes them, so
no microsecond is lost to a JavaScript date. The application reads the three newly paged listings to
their end until W7.3 makes their filters the service's.

**W7.2.** People page by when each first appeared, invited or signed in, not by name: a name is changed in place at every
sign-in, and a key that moves would repeat or skip one. The picker sorts them by name once it holds
them all. Spaces carry the readable set in the query rather than deciding each after reading it, so a
page is never short. API-007's test is taken from the contract: every route answering a list must be
addressed in it and walked, so a listing added later without a cursor fails it.
