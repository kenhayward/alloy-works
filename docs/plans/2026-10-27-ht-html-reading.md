# HT: The HTML reading format

> T6's eighth slice. **Full tier**: layout schema 9, the store's format constraints (0168), the
> publication contract, and tenant content served to a browser
> ([ADR-0070](../decisions/0070-html-is-a-third-output-served-sandboxed.md)). Ken chose it on
> 2026-10-27. **(default)** unless marked **(Ken)**, which waits on [the questions](#questions-for-ken).
> The pre-flight review's findings are folded in.

**Goal:** a publication can be made as one HTML file to read on a screen (PUB-056), written from the
same published document as the PDF and Word, styled by the theme's CSS projection and held to WCAG 2.2
AA. It is the first format without pages, so STR-050 and STR-055 become observable.

## Decisions

| ID   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| HT-A | **One self-contained file** (Ken): `{id}.html`, CSS in one `<style>`, images and faces as `data:` URIs, nothing fetched. `writeHtml` in `packages/domain/src/html/`, pure, from the published document and an `HtmlInput` beside it, as `writeDocx` is. Producer `html`, version `html/1`.                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| HT-B | **Faces**: every face the document sets and its fallback chain whole (`ResolvedParagraphStyle.chain`), by `projectFontFaces` with `data:` URLs; all OFL 1.1 (ADR-0010). The theme's `embedding` is a strict `{ pdf, word }`, so HTML reads `pdf`'s flag. Whole files are about 5 MB in base64 with code and maths (Serif 1.52 MB, Mono 1.19, Math 0.84, Naskh 0.32): measured in `publishing-budget.test.ts` at HTa, and subsetting is taken up in this slice if the default theme's corpus case passes 3 MB.                                                                                                                                                                                                                               |
| HT-C | **The theme's CSS projection**: `projectCss` with `capHeight` (carried in `HtmlInput`), the canvas rules the renderer adds (`CANVAS_CSS`), and the image sizing it does at runtime (`sizeImages`) written statically. The writer emits the markup `renderContent` makes, held by a parity test. Paper and ink, no dark variant (themes.md, STY-Q04). The column is the PDF's text measure, every size being made against it, as a `max-width`; images and tables at most 100%, a wide table scrolling in its own labelled region, so the page reflows at 320 CSS px (WCAG 1.4.10).                                                                                                                                                          |
| HT-D | **`formats.html: {}`, layout schema 9**: it only declares that the layout makes HTML. Optional at every version, as `docx` was at 5, and pagedness is the format's kind, not stored (publishing.md's STR-050 row reworded). **`words` gains `notes`, `backToReference` and `scrollRegion`**, optional before 9, required from 9 and in every translation; fr and de given. Write paths, each tested to keep `html`: the schema and migration chain, `layoutIn` (which rebuilds `formats` naming `pdf` and `docx`), `defaultLayout`, `versions.ts`'s `parseLayout`, `documents.ts`'s offer, `layoutFormats` (HT-G), and 0168's default layout version. PUB-014's tests, which use `html` as the unsupported format, move to an invented one. |
| HT-E | **Formats and contract**: `PUBLISHING_FORMATS` gains `html`; `OUTPUT_CONTENT_TYPES.html`. 0168: any non-empty ordered subset in place of the enumerated `formats` checks; `publication_output` takes `html` (no standard, producer `html`, a report for `docx` or `html`); a preview stays the PDF. The request's description, an `HtmlOutputView`, `SharedOutput` (db and contract), the share route's `SERVED`, the audit kinds (`kinds.ts`), and the renderer's `formats.ts`, `failures.ts`, `BaselinesTab` and `PublicationPage` name it.                                                                                                                                                                                               |
| HT-F | **`assemble` told `html`**: `publishing/26` unchanged, so the PDF beside HTML is the PDF alone. Where `html` is asked it returns `html: HtmlInput` (as `word`): the resolved theme, cap heights, each reference's HTML text by `inlineReferenceKey`, each section title's. `page_reference_without_pages` is a failure only where `html` is asked.                                                                                                                                                                                                                                                                                                                                                                                          |
| HT-G | **Pages** (STR-050, STR-055): `pageBreak` and `appendices.newPage` produce nothing and nothing reports them (#234: nothing honours them yet, so the test sets both). A page reference prints its `withoutPages` form as a link; one without fails `page_reference_without_pages`, naming it. The editor stores `withoutPages` null by default, so **a gate publishes paged formats only** (`layoutFormats`): a gate's publication never fails for a format nobody chose. HTML is chosen in the panel. PUB-074's door read as Ken answers.                                                                                                                                                                                                   |
| HT-H | **Equations as MathML Core from the maths tree** (`mathml.ts` beside `omml.ts`, PUB-067's rule kept): `display="block"` where displayed, `alttext` its alternative, a number beside it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| HT-I | **Footnotes** (Ken): at the end of the top-level section, `<section role="doc-endnotes" aria-labelledby>` headed by `words.notes`, an `<ol>` of `<li id>`; the anchor an `<a role="doc-noteref">`, each note's `<a role="doc-backlink">` named by `words.backToReference`; the numbering table's labels. A table's lettered notes stay under it.                                                                                                                                                                                                                                                                                                                                                                                            |
| HT-J | **Links and matter**: references, citations, terms, contents and lists link to the anchors the document carries; contents a `<nav>` to the layout's depth, no page numbers. A `<header>` holds title, revision and status; the notice is said once. Headings `h1` to `h6`, deeper `role="heading"` with `aria-level`. Hyperlinks keep the model's allowlisted schemes, `rel="noopener noreferrer"`, never `target`.                                                                                                                                                                                                                                                                                                                         |
| HT-K | **The report** (described, PUB-055 not claimed: other exports do not report yet): the output's report on its row, as Word's. Adds `pages_not_carried` (once, where the PDF prints page numbers) and `running_matter_not_carried` (once, where the PDF sets running heads or feet); reuses `table_reflowed`, its sentence reworded to name the output.                                                                                                                                                                                                                                                                                                                                                                                       |
| HT-L | **Content is data**: one `escapeText`, one `escapeAttribute`; no `<script>`, no `on*`, every URL a fragment, the writer's `data:` or an allowlisted hyperlink. In `<head>`, first, the meta CSP (`default-src 'none'; style-src 'unsafe-inline'; img-src data:; font-src data:; base-uri 'none'; form-action 'none'`), then `<meta name="referrer" content="no-referrer">`. A hostile-content test through every kind. **The leak scan** (REU-048): `htmlText` reads attribute values too (`alt`, `aria-label`, `title`, `alttext`), a probe test per attribute; Word's `descr` gap filed as an issue.                                                                                                                                      |
| HT-M | **Served** (ADR-0070): the output route gains an inline variant for `html` alone, for readers inside the organisation, with CSP `sandbox; default-src 'none'; style-src 'unsafe-inline'; img-src data:; font-src data:; base-uri 'none'; form-action 'none'; frame-ancestors 'none'`, `Cache-Control: private, no-store`, `nosniff`. An outsider's, and every signed store link, stays an attachment.                                                                                                                                                                                                                                                                                                                                       |
| HT-N | **Offered**: a checkbox per format the layout makes, PDF chosen first. The publication page: **Download**, and in a browser tab **Open** (the inline route in a new tab). The desktop offers Download only: `setWindowOpenHandler` sends http(s) to the system browser, which has no session, and a same-window `/v1/` address counts as the renderer; a shell test pins that no `/v1/` path is the renderer.                                                                                                                                                                                                                                                                                                                               |
| HT-O | **Accessibility** (PUB-056): the browser suite opens each corpus case's HTML in pinned Chromium, axe with WCAG 2.2 AA and best-practice tags, no violations; walks at 320 px and 200% text; `lang` and `dir` on every passage in another language, an Arabic and Hebrew case. `measureEditor` over the HTML against `EDITOR_DEVIATIONS`. **No check at each publish** (Ken): PUB-101, Word's, is T8, and the HTML's joins it there.                                                                                                                                                                                                                                                                                                         |
| HT-P | **Determinism and conformance**: pure, `\n`, attributes ordered, the time `publishedAt`; the corpus pins each HTML (`RecordedOutputs.check` gains `html`). Against the PDF, by the worker's `pdfText`: the same text in order once running matter, page numbers and the repeated notice are dropped, notes compared as a set per section; the same labels and alternatives.                                                                                                                                                                                                                                                                                                                                                                 |

## Risks

- **The writer's breadth**: every kind the PDF sets, with `html_not_yet` keeping HTa shippable and an
  exhaustive switch failing a kind added later.
- **The stored shapes**: layout 9's write paths and words, 0168's constraints; migration tests run
  current code on old schemas.

## Questions for Ken

1. **Shape** (HT-A): one self-contained file (recommended), or a zip of HTML, CSS, images and faces?
2. **A check at each publish** (HT-O): defer it to T8 beside Word's PUB-101, with axe over the corpus
   in the browser suite now (recommended); or axe in the publish job itself, its row recorded in
   `recordPublication`'s transaction, which departs from ADR-0030 and widens `publication_check`.
3. **HTML without a PDF** (HT-G): allow it where every page reference declares `withoutPages`, since
   the HTML then cites no page (recommended); or keep PUB-074's refusal whenever one exists.
4. **Footnotes** (HT-I): at the end of each top-level section (recommended), at the end of the
   document, or expandable beside their anchor?
