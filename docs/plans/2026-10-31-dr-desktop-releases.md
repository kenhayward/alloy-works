# DR: Desktop releases

> T6's twelfth slice. **Full tier**: a process boundary (a bridge method and an IPC handler), a file
> the shell stores, a workflow with `contents: write`, and code that replaces the installed
> application. Ken answered its four questions on 2026-10-30, marked **(Ken)**; the rest are
> **(default)**. ADM-051 to ADM-053 carry them (issues #827 to #829). The pre-flight review's findings are folded in.
>
> **Why the address comes first.** An installed copy with no `ALLOY_SERVICE_URL` loads the renderer
> from disk, which cannot sign in (ADR-0022). A release of that would install something that does
> nothing, so DRa makes an installed copy usable before DRb publishes one.

**Goal:** a person installs Alloy Works from a GitHub release, tells it once which environment to
connect to, and is offered each later release, installed on a restart they choose.

## Decisions

| ID   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| DR-A | **Which address** (default): `ALLOY_SERVICE_URL`, then the stored address, then, packaged, the Connect to screen, unpackaged, the dev server. `resolveRendererTarget` (`shell.ts`) gains `storedUrl`; the screen is the packaged renderer file loaded with `hash: '/connect'` (`startsAtConnect`). **The window's target is one mutable current target** that the guards and `rendererTarget` read, replaced before each load (main.ts holds a `const` today, so a window re-pointed at runtime would refuse its own bridge). The renderer file counts as the renderer whatever the target, pinned. A URL target failing to load (`did-fail-load`, main frame) opens the screen, saying the address was unreachable. The variable still wins, so development and the e2e suites are unchanged.                                                                                                                                                                                                |
| DR-B | **The screen is the renderer's** (default), `#/connect` decided in `App` above its chrome (Header, Rail, Environment and Workspace each call `/v1/me` on mount and link to sign-in), so it renders alone from `file://` (ADR-0003: one renderer; its words in the catalogue, its walk under axe). Its language falls back to `navigator.languages`, as already when `/v1/me` fails. It shows only where the bridge offers `connectTo`, an optional member of `PlatformBridge` the web delivery leaves out. One field, the address, and Connect; a refusal says why by name. `PlatformInfo` gains `connectedTo?: string`, so the screen shows the current address.                                                                                                                                                                                                                                                                                                                             |
| DR-C | **The check** (default), in the main process, never the renderer. **The connect channel answers only the packaged renderer file**, never a served page, so an environment cannot re-point the app. `addressDecision(value)` in `shell.ts` refuses anything that is not a URL, credentials, and all but `https:` or `http:` on loopback (`localhost`, `*.localhost`, `127.0.0.1`, `[::1]`): the session cookie is `__Host-` and `Secure`, which Chromium keeps over plain `http` only there. It keeps the origin only (an environment is a hostname). Then `net.fetch(<origin>/v1/me)` with no cookie, `redirect: 'manual'`, a 10 s limit: an environment answers 401 with `code: 'unauthenticated'`; 404 `tenant_not_found` is "Alloy Works, but no environment at this address"; anything else, a redirect included, is "not an Alloy Works environment"; no answer is "unreachable". No new route.                                                                                          |
| DR-D | **Stored** (default) in `connection.json` under `app.getPath('userData')`, `{ schemaVersion: 1, address }`, written to a temporary file and renamed. Not a secret, so no `safeStorage`. Read through `addressDecision`; a file that fails it is ignored and the Connect to screen shown.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| DR-E | **Changed** (Ken) by a tray item, "Connect to another environment", which loads the Connect to screen. Connecting loads the new origin; sessions are per hostname, so the old one is kept, not signed out.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| DR-F | **Released on a close** (Ken): `.github/workflows/release.yml`, on `workflow_run` of CI completing with `success` on a push to `main`, so a red main never ships (ADR-0039); it releases where `version.json`'s tag `vX.Y.Z` does not yet exist, so a failed release retries on the next green run. `windows-latest`; `permissions: contents: write, packages: read`; `NODE_AUTH_TOKEN` from `GITHUB_TOKEN` for GitHub Packages. It builds with `pnpm turbo run build --filter=@alloy-works/desktop...` (not the `package` script, whose `--filter` skips Turborepo's order) and `electron-builder --publish never`, then `gh release create vX.Y.Z --target <head_sha>`, not a draft or prerelease, with the installer, its blockmap and `latest.yml`, notes the version's `CHANGELOG.md` section. `workflow_dispatch` builds and uploads a workflow artifact, publishing nothing, so DRb proves the build before any close. No `continue-on-error`; concurrency `release`, never cancelled. |
| DR-G | **Names and install** (default): `artifactName: AlloyWorks-Setup-${version}.${ext}`. GitHub turns spaces in an asset's name into dots, and `latest.yml` names the file, so today's name would break every update. `publish: { provider: github, owner: kenhayward, repo: alloy-works }` in `electron-builder.yml`, which writes the `app-update.yml` the updater reads; its header's "on a tag" corrected. `nsis.perMachine: false`, so an update never asks for administrator rights. Unsigned (Ken): SmartScreen warns on install; a later decision.                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| DR-H | **The updater** (Ken): `electron-updater` 6.8.10 (the newest at least two weeks old), a devDependency bundled into `dist/main.js` by esbuild as everything but `electron` is, a test pinning that it is not required at run time. The GitHub provider, the repository public so no token. Packaged and Windows only. `autoDownload` off, `autoInstallOnAppQuit` on. Checks 10 s after start and from the tray's "Check for updates". A newer release is offered in a native dialog naming its version: Download or Not now. Progress shows in the tray's menu and the taskbar; done, it asks Restart now or Later, Later installing on the next quit. Closing the last window quits on Windows, which abandons a download; the next start offers it again.                                                                                                                                                                                                                                    |
| DR-I | **Decisions in `shell.ts`** (Ken): `updateStep(state, event)`, pure, returns the next state, the tray item and what to do (ask, download, show progress, install); `main.ts` only wires `autoUpdater`'s events to it. A check the person asked for reports "up to date" or its failure; one at start is silent but for a log line without the release's URL. The shell's words join `desktopWords`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| DR-J | **Claims** (default): ADM-051 to ADM-053 in `system.md`'s requirements owned. ADM-052 and ADM-053 are cited by the shell's and the workflow's pins; whether a release really installs and updates is Ken's, on the first two releases after DRc (0.220.0 installed, 0.221.0 offered), as no suite can hold two releases.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |

## Risks

- **The workflow publishes for real only on a close**: `workflow_dispatch` proves everything but
  `gh release create`, which DRc's close then proves.
- **An unsigned update** installs without a publisher check; signing is the later decision (Ken).
- **`/v1/me`'s 401 as the mark of an environment** holds while it stays session-checked;
  `session-routes.test.ts` pins it.
- **electron-updater 6.8.10 beside electron-builder 26.15.3**'s runtime is unproven: the
  `workflow_dispatch` build and a local update between two builds settle it in DRc.
