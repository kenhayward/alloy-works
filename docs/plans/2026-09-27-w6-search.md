## Global constraints

- Test titles cite only what they show, checked with `pnpm trace show <ID>`, in a literal title; an
  `it.each` title cites nothing, and a `rule:` field in a test cites its requirement.
- Each test is watched fail: a new test before the code, or, where the code exists, by breaking it.
- No em or en dash in user-facing text, and no real names, addresses or paths in a fixture.
- `pnpm typecheck`, `pnpm lint`, `pnpm format`, the affected suites, then `pnpm trace generate` after
  Prettier and `pnpm trace pins`; the full suite before each pull request, and its CI log read, not
  only its checks.
- A new tenant migration is appended to every test that lists the migrations.

## W6.1: The projection

1. **The entry, pure** (`domain: src/search/`): `entriesOf(version, context)` - an artifact version's
   entries and their text rows, per kind, as search.md's table gives them; `configurationFor(language)`.
   **Tests:** `SCH-002 covers content, metadata, titles, captions and alternative text` (a component
   with a figure, a table, a footnote and values; an asset's description); uncited: each kind's rows, a
   section an entry of its own, the language map.
2. **Storage** (`0031_search.sql`, `db: src/search.ts`): the two tables, GIN on the `tsvector`;
   `indexArtifact` called from `createArtifact`, `recordVersion` and `recordPublication`, a
   publication having no versions; `reindexSearch`; the `search.reindex` job, enqueued by `migrate`
   for each tenant whose run applied 0031 - a tenant migration runs as the owner role, which cannot
   write the platform's job table. **Tests:** `SCH-054 makes every kind searchable`
   (one of each, found by a word it holds); `SCH-066 makes a new version findable by its words in the
next transaction`; uncited: a changed version replaces its rows, reindex rebuilds a tenant's.
3. Docs.

## W6.2: The query

1. **`parseQuery`** (`domain`): NFC, scopes, the outcomes. **Tests:** `SCH-011 supports phrases,
exclusion and field-scoped terms`; `SCH-012 matches two strings a reader cannot tell apart`;
   `SCH-039 names an empty or malformed query rather than answering it`.
2. **The statement** (`db: searchWords`): the readable set, the predicate, the best place per entry,
   the passage, the count capped. **Tests:** `SCH-016 shows each result with a passage from where it
matched`; `SCH-017 names the place a result matched`; `SCH-010 finds nothing a user may not read,
by every path, counts included` (a leak suite over components, documents, sections, publications,
   templates, assets and definitions, as a user with no read on any of them).
3. **The route**: `GET /v1/search?q=`, signed in; the outcomes with their sentences. Uncited test.
4. Docs.

## What the build changed

**W6.1.** The reindex is run by the migration runner itself, in the transaction that applies 0031 to a
tenant and as its owner role, rather than by a worker job the runner enqueues: a job left an
environment searchable only in part until a worker reached it, needed a job kind and a handler of its
own, and put a job on the queue for every tenant a test made, which the queue's and the worker's tests
would have claimed. SE-C says so. The entries are written by `insertVersion`, which `createArtifact`
and every `recordVersion` reach, and skipped for a tenant with no `search_entry` table yet - only a
test migrated to an earlier point writes one - since 0031's run makes them. A field's value is a place
of its own, `field:<id>`, so a term scoped to a field is matched there alone (W6.2).
