# MF: Message forms in content

> T6's eleventh slice. **Full tier**: a new inline node in stored content, a new unit shape in the
> XLIFF a translator receives, a member of a publication's `locale_data` and published provenance's
> version 6. Ken answered its seven questions on 2026-10-29, each as recommended but exact arms, which
> he took: his four are marked **(Ken)**, the rest **(default)**. LOC-039 is superseded by **LOC-045**
> carrying his answers, with a change history. The pre-flight review's findings are folded in.
> **The requirement was right in aim and loose in three words:**
>
> - **"The same mechanism as the interface" cannot mean the same code.** The interface selects with
>   FormatJS's `Intl.PluralRules`, forced over the browser's (`apps/web/src/words/polyfills.ts`); the
>   worker would select with Node's ICU, which TEc pinned and recorded but which is not FormatJS's
>   CLDR. A value is already printed by the domain's own code, never `Intl`, for exactly this reason
>   (`data/format.ts`, B1-G). So LOC-045 asks for the same _data_ and _rules_: CLDR 48.2.0's cardinal
>   rules compiled into the domain by the generator that already reads `plurals.json`
>   (`scripts/cldr-inputs.ts`), held to `@formatjs/intl-pluralrules` by a parity test.
> - **"A number or a gender"**: no column type is a gender (`data/columns.ts`), and a gender is a
>   `select` over author-chosen keys, not a CLDR category. LOC-045 is plural only, gender a named gap
>   until a column type carries one.
> - **"Must be a message form rather than text assembled"** cannot be enforced: nothing tells a bound
>   number before "items" from one before "kg". The product offers the form and keeps it through every
>   path; it does not refuse a binding outside one (a named gap, MF-J).
>
> **Smaller than the TE plan said.** The binding stage (`publishing/bind.ts`) already replaces each
> binding with a text run before anything writes; a form resolved there to its chosen arm's inlines
> reaches the PDF, Word and HTML writers as ordinary text, so no template, `word/` or `html/` schema
> changes. The cost moves to the write paths, XLIFF and the editor's nested arms.

**Goal:** an author writes a sentence that varies by a bound number as a message form whose arms are
the plural categories of the component's language; a translator fills the arms of the variant's own
language; a publish selects the arm the value calls for, the same in the editor and every output
(LOC-045).

## Risks

- **The rule compiler is new code over CLDR's syntax** (`and`, `or`, ranges, `%`): CLDR's own samples
  test it, and FormatJS parity catches a misread.
- **XLIFF tools may drop notes or reorder units**: arms come back by key, never by order; a missing
  unit leaves the arm empty and the import says so.
- **A nested view per arm**: footnotes proved the pattern, not six of them in one chip; measured in
  MFd on the editor walk.
- **Data changes after translation**: a value moving from 2 to 3 in Arabic selects `few`, which an
  older variant may lack; MF-E fails the publish by name, never prints another arm.
