| FR-C | **Captured at a run**: the run answers an opaque `revision`, at most 256 characters, and provenance gains it as an optional top-level member (whether the dataset's identity covers it is checked first, and it is kept outside if so). | FR-D | **Asked at a check** (DAT-084): after the identity gates and within the 50-question cap, where the held version names a connection (never a stored result's, R21), carries a `revision`, and was made by the definition version, connection version and values the check would run, the service asks the connector's `/v1/revision`, sent the run request it would send, identity included. ## Risks

- **A token proves less than a checksum**: a server whose ETag does not move with its content is believed; the next run still verifies its checksum.
- **A revision statement is the author's word**: one that does not move with the data hides a change until a person refreshes.
- **An S3 ETag is not a digest** (multipart, KMS): it still moves when an object is rewritten, which is all the check asks.
- **DAT-073's tests** show no run reaching the connector on an unchanged revision for each of HTTP, S3 and PostgreSQL, the last against the suite's own PostgreSQL.
